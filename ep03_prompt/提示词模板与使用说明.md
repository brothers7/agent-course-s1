# 第三集：提示词模板与使用说明

以下是课程教学模板，不是模型效果保证。可用于聊天界面，也可按服务的消息角色约定接入第二集程序。模型可能不遵守某些要求，输出仍需检查。

## 固定规则

可直接复制 `prompt_builder.py` 中 `RULES` 的完整文字。它包含职责、任务、缺失条件的处理、事实边界、五项交付和一个短示例。不要将不可信网页全文或用户材料拼进这部分。

## 本次输入模板

```text
主题：[填写主题]
受众：[填写已有基础与使用场景]
选题数量：[填写数量]
单条时长：[填写分钟数]
时间范围：[演示与安装是否计入]
素材：[粘贴允许发送的实际内容，或如实说明尚未提供]
```

方括号是填写提示，请替换后使用。模板中的“主题、受众、时长、数量”缺失时，完整规则要求模型先提问。若内容依赖某份文档，应先提供允许使用的文档或摘要。仅写“我有一本手册”不代表模型看到了手册。

## 本地离线预览

脚本只使用 Python 标准库，不安装新依赖，不读取密钥，不发送请求。在本文件所在目录运行：

macOS / Linux：

```bash
python3 prompt_builder.py --variant structured
python3 prompt_builder.py --variant base
```

Windows PowerShell：

```powershell
py prompt_builder.py --variant structured
py prompt_builder.py --variant base
```

两次预览使用完全相同的 `TASK`，仅改变固定规则。`YOUR_MODEL_ID` 是占位符，不能直接作为真实模型标识使用。`system` 与 `developer` 的支持范围以所用模型的官方文档为准，脚本不会探测兼容性。

## 接到第二集程序（可选实操）

先复制一份第二集“示例代码”目录作为新练习项目，保留原文件。将 `prompt_builder.py` 放在副本的 `app.py` 同目录。保持第二集的依赖、地址、密钥读取、发送与异常处理不变。

1. 在 `app.py` 的导入区增加：

```python
import json
from prompt_builder import TASK, make_payload as make_task_payload
```

2. 将 `main()` 中原本的 `payload = make_payload(model, prompt)` 这一行替换为：

```python
task_input = json.dumps(TASK, ensure_ascii=False, indent=2)
payload = make_task_payload(model, task_input, variant="structured")
```

3. 本练习不再使用第二集的 `--variant base/demo` 参数。A/B 切换只修改上一段的 `variant="base"` 或 `variant="structured"`，不要同时改 `TASK`。第二集旧参数暂留不影响调用，但不会控制本集规则。

4. 只有主动运行修改后的 `app.py` 才会发起真实模型请求，并可能产生费用。录制前先确认所用模型支持该兼容协议与非流式文字返回。若官方要求 `developer`，在 `make_task_payload` 中传入 `rules_role="developer"`。其他协议需按文档适配，不能靠改角色名解决。

5. 先用非敏感输入做少量测试。不要展示密钥、请求头、私人素材或未经允许的第三方内容。数据不足时可以只用离线样例讲解，但必须保留“教学样例”标注。

本资料包没有读取用户凭证，也没有执行真实模型请求。离线组装测试只能验证消息结构，不能证明提示词效果或线上接口兼容性。
