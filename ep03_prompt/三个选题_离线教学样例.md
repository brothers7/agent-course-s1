# 三个选题：离线教学样例

以下是为讲解而编写的策划草稿，不是真实模型返回或测试记录。每条计划 7 分钟，包含演示、不包含安装。没有实际日志或外部资料，不宣称已经运行或验证。

## 1. 给 AI 一份能执行的任务

**学习目标**：把一句宽泛要求改写成包含任务、输入、约束与交付的任务说明。

**演示步骤（计划）**：

1. 输入同一份 Agent 入门主题、受众和 7 分钟条件。
2. 用简单规则 A 与完整规则 B 各调用一次，其他配置不变。
3. 在终端查看输出，用同一张检查表记录缺项，不要求措辞与样例一致。

**时间安排**：问题 1 分钟，任务改写 2 分钟，对照演示 3 分钟，总结 1 分钟。合计 7 分钟。

**依据或待核实项**：已提供的是策划条件与计划录制的素材清单，没有实际运行证据。两次调用的结果、遗漏项和请求耗时均待实测。某个版本是否更好，需要后续多个固定样例验证。

## 2. 一次 API 调用，文字去了哪里？

**学习目标**：在非流式 Chat Completions 兼容调用中，区分输入消息与返回文字。

**演示步骤（计划）**：

1. 输入“生成 3 个 Agent 选题”，仅展示脱敏的请求体，不展示密钥或请求头。
2. 运行第二集程序一次，观察终端打印出的文字。
3. 在代码中对照 `messages` 与 `choices[0].message.content` 的位置，指出实际字段应以所用服务文档为准。

**时间安排**：问题 1 分钟，请求与返回讲解 2 分钟，程序演示 3 分钟，总结 1 分钟。合计 7 分钟。

**依据或待核实项**：尚未提供日志。实际模型、非流式支持与响应格式待核对服务文档并试跑。这里不编造真实返回文字，也不声称所有模型使用同一协议。

## 3. 模型答偏了，先检查输入还是连接？

**学习目标**：区分“请求失败”与“成功收到但不满足任务的内容”，确定下一步检查位置。

**演示步骤（计划）**：

1. 准备一份明确标注为模拟的 HTTP 401 错误文本，与一份没有演示建议的离线选题文本。
2. 对前者检查服务配置的类别，对后者对照实际任务要求，说明不需要因内容不理想就更换密钥。
3. 将“需要演示”改成“说明输入、操作与观察点”，展示改写后的任务。要展示效果，另行试跑并保留真实记录。

**时间安排**：问题 1 分钟，两类现象对照 2 分钟，任务改写 2 分钟，观众判断 1 分钟，总结 1 分钟。合计 7 分钟。

**依据或待核实项**：错误与输出均为教学模拟，不代表已发生的线上错误。真实状态码含义、错误详情和改写效果待所用服务文档及运行记录确认。

## 人工检查范围

本例检查的是草稿是否包含五项内容、是否给出具体观察点、时间是否合计正确、是否如实标注缺证据。计划时间不保证真实录制时长。例子之间有课程主题关联，可根据自己的赛道进一步拉开选题差异。
